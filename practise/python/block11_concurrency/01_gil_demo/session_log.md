# Session log — block11 / 01_gil_demo

Окружение: Python 3.13.2 (сборка с GIL, не free-threaded), macOS.

## Прогноз (до запуска), T = cpu x1
- cpu x4 ≈ 4T
- io  x1 ≈ 2 с
- io  x4 ≈ 2 с

## Реальные цифры
| запуск | время, с | относительно |
|---|---|---|
| cpu x1 | 0.861 | T |
| cpu x4 | 3.476 | ≈ 4.04T |
| io  x1 | 2.005 | — |
| io  x4 | 2.007 | ≈ io x1 |

## Вывод
Прогноз совпал во всём. CPU-bound: 4 потока работают ≈ в 4 раза дольше одного, т.е. ускорения нет. GIL сериализует исполнение байткода.
IO-bound: `sleep` отпускает GIL, поэтому 4 ожидания перекрываются, и общее время ≈ одному ожиданию.
(Вывод сформулирован Claude по просьбе Вадима, сам Вадим сказал: «был прав во всём».)

## Вопросы и уточнения по ходу
- Уточнял, что делает `run(target, k)`. Сначала понял это как «запуск k раз». Поправка: создаются k потоков, каждый выполняет `target` один раз, все стартуют одновременно, замеряется общее wall-time до `join` последнего.
- Ошибок в прогнозе не было.
